7  Предобработка данных. Строки. Дата и время

Числа и логические значения обрабатывать просто: у них есть чёткие правила арифметики. С текстом и со временем сложнее. Названия файлов, ответы на открытые вопросы, имена стимулов, даты прохождения опроса — всё это данные, которые нужно уметь «разбирать на части», проверять на соответствие шаблону и приводить к единому виду. Здесь нам поможет два пакета из tidyverse: stringr для строк и lubridate для даты и времени.

7.1 Строки

7.1.1 Строка как тип данных

С типом character мы познакомились в основах R. Напомним главное: строка — это последовательность символов, заключённая в кавычки, а строковый вектор (character vector) — вектор, элементами которого являются строки.

Строки можно заключать как в двойные, так и в одинарные кавычки:

s1 <- "tray1.png"
s2 <- 'dots2.png'
c(s1, s2)
[1] "tray1.png" "dots2.png"

Если внутри строки нужны кавычки, то можно заключить строку в кавычки другого вида:

s3 <- 'Испытуемый сказал: "Я ничего не нашёл"'
s3
[1] "Испытуемый сказал: \"Я ничего не нашёл\""
cat(s3)
Испытуемый сказал: "Я ничего не нашёл"

Обратите внимание на разницу между выводом s3 и cat(s3). В первом случае R показывает строку «как она записана в коде» — и поэтому внутренние кавычки экранируются обратным слэшем (\"). Во втором — выводит именно текст, как он есть.

Если в строке нужны кавычки того же вида, их экранируют обратным слэшем \: "Он сказал: \"Привет\"". Символ \ в R — служебный: например, \n означает перевод строки, а \t — табуляцию.

7.1.2 Пакет stringr

Для работы со строками существует два основных пакета: stringr (входит в tidyverse) и более мощный stringi (устанавливается отдельно). Мы будем пользоваться первым. Все его функции начинаются с str_, что облегчает поиск нужной функции в подсказках RStudio: достаточно набрать str_ и нажать Tab.

Строки в данных нам встречались давно. Например, путь к файлу и его имя:

files <- dir("data/sharexp/raw", full.names = TRUE)
files[1:3]
[1] "data/sharexp/raw/01.csv" "data/sharexp/raw/02.csv"
[3] "data/sharexp/raw/03.csv"

7.1.3 Длина, регистр, подстроки

Количество символов в строке возвращает str_length():

str_length(files[1:3])
[1] 23 23 23

Привести строку к верхнему или нижнему регистру можно функциями str_to_upper() и str_to_lower(), а сделать заглавной первую букву — str_to_sentence() или str_to_title():

str_to_upper("tray1.png")
[1] "TRAY1.PNG"
str_to_title("search time by set size")
[1] "Search Time By Set Size"

Приведение к единому регистру — обязательный шаг при работе с ответами респондентов: «Москва», «москва» и «МОСКВА» для R — три разных значения, а для нас — одно.

Выделить часть строки по позициям символов можно с помощью str_sub():

str_sub("sharexp", start = 1, end = 5)
[1] "share"
str_sub("sharexp", start = -3)          # отрицательные значения --- с конца строки
[1] "exp"

Часто лишние пробелы в начале и в конце строки (особенно в данных, набранных руками) мешают сопоставлению. Убрать их можно функцией str_trim():

str_trim("   Android ")
[1] "Android"

7.1.4 Склеивание и разделение

Склеить строки можно с помощью str_c() (в базовом R — paste() и paste0()). Аргумент sep задаёт разделитель, который будет поставлен между склеиваемыми строками. Функция векторизована, поэтому склеивает вектора поэлементно (вспомните recycling):

str_c("id", 1:3, sep = "_")
[1] "id_1" "id_2" "id_3"
str_c("trial", 1:3, collapse = ", ")   # collapse склеивает элементы вектора в одну строку
[1] "trial1, trial2, trial3"

Если нужно «дополнить» числа нулями слева, чтобы они имели одинаковую длину (как в именах наших файлов 01.csv, …, 20.csv), поможет str_pad():

str_pad(1:12, width = 2, pad = "0")
 [1] "01" "02" "03" "04" "05" "06" "07" "08" "09" "10" "11" "12"

Разделить строку по символу можно функцией str_split(). Она возвращает список: для каждой исходной строки — вектор её частей.

str_split("tray1.png", pattern = "\\.")
[[1]]
[1] "tray1" "png"

(Точка перед png записана как "\\." — об этой странности чуть позже, в разделе про регулярные выражения.)

Если вам нужен не список, а таблица, то разделять и склеивать можно прямо в таблицах — с помощью функций separate_wider_delim() и unite() из tidyr. Мы воспользуемся ими уже скоро.

7.1.5 Поиск и замена

Самая частая задача — найти в строках некий фрагмент. Рассмотрим на примере реальных данных. В файлах PsychoPy в столбцах stim1, stim2, … записаны названия графических файлов со стимулами, которые предъявлялись в пробе. Посмотрим на стимулы первой пробы первого испытуемого:

d1 <- read_csv("data/sharexp/raw/01.csv", show_col_types = FALSE)

stim <- d1[1, paste0("stim", 1:8)] |> unlist(use.names = FALSE)
stim
[1] "tray1.png" "01.png"    "02.png"    "03.png"    "04.png"    "05.png"   
[7] "06.png"    "07.png"

В пробе 8 стимулов (setsize = 8). Все они называются по-разному: один содержит tray, остальные — просто числа. Судя по названиям, tray1.png — это иконка Outgoing Tray, то есть целевой стимул, а числа — дистракторы.

Функция str_detect() проверяет, есть ли в строке заданный фрагмент (шаблон), и возвращает вектор из TRUE и FALSE:

str_detect(stim, "tray")
[1]  TRUE FALSE FALSE FALSE FALSE FALSE FALSE FALSE

Эту функцию удобно использовать внутри filter() и mutate():

tibble(stim = stim) |>
  filter(str_detect(stim, "tray"))
# A tibble: 1 × 1
  stim     
  <chr>    
1 tray1.png

Чтобы посчитать число вхождений шаблона в строку, есть str_count(), чтобы извлечь сам шаблон — str_extract(), чтобы заменить его — str_replace(), чтобы удалить — str_remove():

str_count(stim, "\\d")                  # сколько цифр в каждой строке
[1] 1 2 2 2 2 2 2 2
str_extract(stim, "\\d+")               # достаём числа из названий
[1] "1"  "01" "02" "03" "04" "05" "06" "07"
str_replace(stim, "\\.png$", ".jpg")    # меняем расширение
[1] "tray1.jpg" "01.jpg"    "02.jpg"    "03.jpg"    "04.jpg"    "05.jpg"   
[7] "06.jpg"    "07.jpg"   
str_remove(stim, "\\.png$")             # убираем расширение
[1] "tray1" "01"    "02"    "03"    "04"    "05"    "06"    "07"

Все эти функции принимают в качестве шаблона не просто текст, а регулярное выражение — и именно оно скрывается за странными символами \\d+ и \\.png$. Разберёмся.

7.2 Регулярные выражения

Определение 7.1 Регулярное выражение (regular expression, regex) — это текстовый шаблон, который описывает множество строк. Он состоит из обычных символов, которые обозначают самих себя, и метасимволов, которые обозначают «что-то особенное».

Регулярное выражение — язык для описания паттернов в тексте. Он существует практически во всех языках программирования. Выучить его целиком невозможно, да и не нужно. Мы разберём минимально необходимое.

Чтобы на практике увидеть, что находит шаблон, воспользуемся функцией str_view(): она выводит строки и подсвечивает найденные фрагменты. Возьмём вектор дат, записанных в разных форматах (в том числе с ошибками, которые мы хотим научиться находить):

dates <- c("21.92.2001", "19.11.12", "16.o1.2001", "01.04.1994", "5-3-2011", "6/04/1999")
dates
[1] "21.92.2001" "19.11.12"   "16.o1.2001" "01.04.1994" "5-3-2011"  
[6] "6/04/1999"

7.2.1 Метасимволы

Метасимволы — это символы, у которых есть особое значение:

str_view(dates, ".")    # любой символ --- подсвечивается всё
[1] │ <2><1><.><9><2><.><2><0><0><1>
[2] │ <1><9><.><1><1><.><1><2>
[3] │ <1><6><.><o><1><.><2><0><0><1>
[4] │ <0><1><.><0><4><.><1><9><9><4>
[5] │ <5><-><3><-><2><0><1><1>
[6] │ <6></><0><4></><1><9><9><9>

Точка — это любой символ, поэтому она нашла всё. Чтобы найти именно точку, нужно «лишить» её особого смысла — экранировать обратным слэшем. А поскольку обратный слэш в R-строке сам служебный, его приходится удваивать:

str_view(dates, "\\.")  # именно точка
[1] │ 21<.>92<.>2001
[2] │ 19<.>11<.>12
[3] │ 16<.>o1<.>2001
[4] │ 01<.>04<.>1994

Это то самое «странное» \\. из примеров выше. Чтобы найти строки, которые начинаются с нуля, или заканчиваются на девятку, используют ^ и $:

str_view(dates, "^0")   # начинается с нуля
[4] │ <0>1.04.1994
str_view(dates, "9$")   # заканчивается на девятку
[6] │ 6/04/199<9>

Для классов символов (цифры, пробелы, буквы) используют обозначения с обратным слэшем:

str_view(dates, "\\d")  # цифры
[1] │ <2><1>.<9><2>.<2><0><0><1>
[2] │ <1><9>.<1><1>.<1><2>
[3] │ <1><6>.o<1>.<2><0><0><1>
[4] │ <0><1>.<0><4>.<1><9><9><4>
[5] │ <5>-<3>-<2><0><1><1>
[6] │ <6>/<0><4>/<1><9><9><9>
str_view(dates, "\\D")  # всё, кроме цифр
[1] │ 21<.>92<.>2001
[2] │ 19<.>11<.>12
[3] │ 16<.><o>1<.>2001
[4] │ 01<.>04<.>1994
[5] │ 5<->3<->2011
[6] │ 6</>04</>1999

7.2.2 Квантификаторы

Часто нужно указать, сколько раз повторяется символ или группа символов. Для этого используются квантификаторы:

str_view(dates, "\\d{2}")   # ровно две цифры подряд
[1] │ <21>.<92>.<20><01>
[2] │ <19>.<11>.<12>
[3] │ <16>.o1.<20><01>
[4] │ <01>.<04>.<19><94>
[5] │ 5-3-<20><11>
[6] │ 6/<04>/<19><99>
str_view(dates, "\\d+")     # одна или более цифр подряд
[1] │ <21>.<92>.<2001>
[2] │ <19>.<11>.<12>
[3] │ <16>.o<1>.<2001>
[4] │ <01>.<04>.<1994>
[5] │ <5>-<3>-<2011>
[6] │ <6>/<04>/<1999>

7.2.3 Строим регулярное выражение шаг за шагом

Теперь решим практическую задачу: из вектора dates отобрать корректные даты в формате дд.мм.гггг. Строить регулярное выражение лучше постепенно, проверяя каждый шаг. Для проверки будем использовать str_detect().

Шаг 1. В дате должны быть точки.

str_detect(dates, "\\.")
[1]  TRUE  TRUE  TRUE  TRUE FALSE FALSE

Отсеялись даты с другими разделителями (5-3-2011, 6/04/1999).

Шаг 2. Между точками — только цифры, а во всей строке нет ничего лишнего. Для этого зафиксируем начало и конец строки.

str_detect(dates, "^\\d+\\.\\d+\\.\\d+$")
[1]  TRUE  TRUE FALSE  TRUE FALSE FALSE

Отсеялась дата 16.o1.2001 — в ней вместо нуля закралась латинская буква «o».

Шаг 3. Уточним: две цифры в дне, две в месяце, четыре в году.

str_detect(dates, "^\\d{2}\\.\\d{2}\\.\\d{4}$")
[1]  TRUE FALSE FALSE  TRUE FALSE FALSE

Отсеялась дата 19.11.12 — в ней двузначный год.

Шаг 4. Но ведь 21.92.2001 соответствует нашему шаблону, хотя месяца 92 не бывает. Ограничим допустимые цифры: в дне первая цифра от 0 до 3, в месяце — 0 или 1.

str_detect(dates, "^[0-3]\\d\\.[01]\\d\\.\\d{4}$")
[1] FALSE FALSE FALSE  TRUE FALSE FALSE

Теперь остаётся единственная корректная дата. Можно сделать шаблон ещё строже — чтобы он не пропускал, например, 39 число или 19-й месяц:

str_detect(dates, "^(0[1-9]|[12]\\d|3[01])\\.(0[1-9]|1[0-2])\\.\\d{4}$")
[1] FALSE FALSE FALSE  TRUE FALSE FALSE

Здесь (0[1-9]|[12]\\d|3[01]) читается так: «ноль и цифра от 1 до 9, или 1 или 2 и любая цифра, или 3 и 0 или 1» — то есть число от 01 до 31.

Совет

Регулярные выражения читаются и пишутся тяжело даже опытными программистами. Тестируйте их на небольших примерах, стройте постепенно, а за подсказкой обращайтесь к справочнику — в RStudio он открывается через Help → Cheat Sheets → String Manipulation with stringr. Сервисы вроде regex101.com показывают, что именно находит шаблон.

7.3 Разделение значений: строки внутри данных

Теперь вернёмся к реальным данным. Помните, что в главе про опрятные данные мы заметили, что в sharexp в одной ячейке иногда лежат два значения? Посмотрим на позиции стимулов в пробе:

d1$pos1[1:5]
[1] "[-238, 202]" "[-213, 226]" "[-234, 217]" "[-247, 218]" "[-243, 209]"

Каждая позиция — строка вида "[-238, 202]", внутри которой записаны две координаты: x и y. Это нарушение третьего принципа опрятных данных. Расщепим эту строку на два числовых столбца.

Сначала уберём квадратные скобки. Они в регулярных выражениях имеют особое значение (границы класса символов), поэтому их нужно экранировать, а внутри класса [...] — перечислить:

pos <- d1$pos1[1:5]
str_remove_all(pos, "[\\[\\]]")
[1] "-238, 202" "-213, 226" "-234, 217" "-247, 218" "-243, 209"

Теперь разделим по запятой и пробелу. Для таблиц это удобнее делать функцией separate_wider_delim():

tibble(pos1 = d1$pos1[1:5]) |>
  mutate(pos1 = str_remove_all(pos1, "[\\[\\]]")) |>
  separate_wider_delim(pos1, delim = ", ", names = c("pos1x", "pos1y"))
# A tibble: 5 × 2
  pos1x pos1y
  <chr> <chr>
1 -238  202  
2 -213  226  
3 -234  217  
4 -247  218  
5 -243  209

Разделилось, но столбцы по-прежнему текстовые (<chr>). Превратим их в числа:

tibble(pos1 = d1$pos1[1:5]) |>
  mutate(pos1 = str_remove_all(pos1, "[\\[\\]]")) |>
  separate_wider_delim(pos1, delim = ", ", names = c("pos1x", "pos1y")) |>
  mutate(across(everything(), as.numeric))
# A tibble: 5 × 2
  pos1x pos1y
  <dbl> <dbl>
1  -238   202
2  -213   226
3  -234   217
4  -247   218
5  -243   209

Вот теперь данные опрятные. Если же нужно просто «выдернуть» числа из строки, можно воспользоваться str_extract_all() с шаблоном «необязательный минус и одна или более цифр»:

str_extract_all(pos, "-?\\d+")
[[1]]
[1] "-238" "202" 

[[2]]
[1] "-213" "226" 

[[3]]
[1] "-234" "217" 

[[4]]
[1] "-247" "218" 

[[5]]
[1] "-243" "209"

Или parse_number() из readr — она извлекает первое число из текста (мы уже использовали её для идентификатора испытуемого).

Противоположная операция — склеивание нескольких столбцов в один — называется unite(). Например, сделаем «подпись» условия из типа пробы и количества стимулов:

tibble(trialtype = c("tray", "dots"), setsize = c(8, 16)) |>
  unite("condition", trialtype, setsize, sep = "_")
# A tibble: 2 × 1
  condition
  <chr>    
1 tray_8   
2 dots_16

7.4 Дата и время

7.4.1 Почему дата и время — особый тип данных

Казалось бы, дату можно хранить как обычную строку или как три числа. Но у времени есть много неочевидных особенностей, которые делают наивные вычисления опасными:

  • год не всегда равен 365 дням (бывают високосные годы);
  • сутки не всегда состоят из 24 часов (переходы на зимнее и летнее время; хотя в России эти переходы отменены, остальной мир продолжает их использовать);
  • в месяцах разное число дней;
  • одно и то же время в разных часовых поясах записывается по-разному;
  • даты записывают в десятке разных форматов.

Чтобы не вспоминать правила календаря каждый раз, мы пользуемся специальными типами данных, а в R за работу с ними отвечает пакет lubridate (он входит в tidyverse).

Получить текущую дату и текущий момент времени можно так:

today()   # текущая дата
now()     # текущий момент времени

7.4.2 Форматы даты и времени

Даты в мире записывают по-разному:

Опасность в том, что запись 02/03/2019 в Европе означает 2 марта, а в США — 3 февраля. Без дополнительной информации определить формат невозможно.

Важность

Если у вас есть возможность выбирать формат записи дат при сборе данных, выбирайте гггг-мм-дд. Он однозначен, и при сортировке строк в алфавитном порядке даты оказываются в хронологическом порядке.

7.4.3 Читаем даты из sharexp

Предупреждение

Разбор названий месяцев (Jan, May и т. д.) в lubridate зависит от языковых настроек операционной системы, и на устройстве с другой локалью он может не сработать. Поэтому мы сначала заменили названия месяцев числами. Этот приём заодно показывает, что с помощью строковых функций можно подготовить к разбору даже весьма неудобные форматы.

Если бы нам встретились даты в разных порядках (например, где-то дд.мм.гггг, а где-то мм.дд.гггг), то сам по себе код не смог бы их различить. В таком случае нужно разбираться, откуда пришли данные. В наших данных порядок год_месяц_день однозначно следует из записей со словами (2019_Jan_14: после слова может идти только день) и из дат с числом больше 12 на втором месте. Для дат вроде 2019_02_01_1426 теоретически возможно и «1 февраля», и «2 января», но раз все остальные даты записаны в порядке «год — месяц — день», разумно предположить то же самое и здесь. Это допущение, и о нём стоит помнить.

Ещё одно наблюдение: у испытуемых 6 и 10, а также 15 и 16 время начала сессии совпадает до минуты. Возможно, их тестировали параллельно на разных компьютерах, но это стоит уточнить у экспериментатора, а не принимать молча. Здесь мы в очередной раз убеждаемся, что на данные нужно смотреть.

7.4.5 Вычисления с датами

С датами можно производить арифметику. Разность двух дат — это промежуток времени, и для его вычисления лучше использовать difftime() с явным указанием единиц измерения:

first_session <- min(sessions$session_start)
last_session <- max(sessions$session_start)

first_session
[1] "2019-01-14 10:38:00 UTC"
last_session
[1] "2019-05-16 10:32:00 UTC"
difftime(last_session, first_session, units = "days")
Time difference of 121.9958 days

Между первой и последней сессией прошло около 122 дней — примерно четыре месяца. Чтобы получить это значение как обычное число, а не особый объект, заверните результат в as.numeric():

as.numeric(difftime(last_session, first_session, units = "days"))
[1] 121.9958

К дате можно прибавлять промежутки времени с помощью функций days(), hours(), minutes() и др.:

first_session + days(7)
[1] "2019-01-21 10:38:00 UTC"
first_session + hours(3) + minutes(30)
[1] "2019-01-14 14:08:00 UTC"

Если же нужно превратить дату обратно в текст определённого формата (например, чтобы подписать график или записать в отчёт), используют format():

format(first_session, "%d.%m.%Y %H:%M")
[1] "14.01.2019 10:38"

В шаблоне %d — день, %m — месяц, %Y — год из четырёх цифр, %H — часы, %M — минуты.

7.4.6 Часовые пояса

Момент времени имеет смысл только вместе с часовым поясом. По умолчанию lubridate считает, что время записано в UTC (всемирное координированное время, примерно «время по Гринвичу»). Если известно, что сессии проходили по московскому времени, это нужно указать:

ymd_hm("2019_01_14_1038", tz = "Europe/Moscow")
[1] "2019-01-14 10:38:00 MSK"

Для наших данных это несущественно: все даты мы используем только для сопоставления друг с другом. Но если вы анализируете данные, собранные в разных часовых поясах (например, в онлайн-исследовании), о часовых поясах забывать нельзя — иначе «ночные» ответы окажутся дневными, а порядок событий исказится.

ЗаметкаИтоги
  • Строки обрабатываются функциями stringr (str_*): длина — str_length(), регистр — str_to_lower() / str_to_upper(), подстрока — str_sub(), склейка — str_c(), поиск — str_detect(), str_extract(), замена — str_replace(), str_remove(), разделение — str_split() и separate_wider_delim().
  • Регулярные выражения — язык для описания шаблонов в тексте. Метасимволы (., ^, $, \\d, [...]) и квантификаторы (?, +, *, {n}) позволяют искать и проверять строки. Строить выражение нужно постепенно, проверяя каждый шаг.
  • Если в ячейке больше одного значения, данные не опрятные: значения нужно расщепить (separate_wider_delim()) и привести к числовому типу.
  • Дата и время — особый тип данных. Для их чтения служат ymd(), dmy(), ymd_hm() и родственные функции из lubridate, для извлечения компонентов — year(), month(), wday(), hour() и др., для вычисления разности — difftime().
  • Формат записи даты нужно выяснять, а не угадывать: 02/03/2019 может быть и второе марта, и третье февраля.
